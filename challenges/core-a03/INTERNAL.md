# core-a03 internal notes

This challenge models an internal project-approval portal. Login is stored server-side, but the `portal_state` cookie is an unsigned base64 JSON context generated by the workspace selector. The approval queue and privileged review page incorrectly use `workspace == leadership` plus the client-provided `persona == admin` as the effective role.

The solver must observe the normal workspace request, decode and modify the existing client context, then request the privileged review page and its dynamically generated archive URL. `VARIANT_SEED` changes the project identifier; the archive token is per container process and the archive contains `INSTANCE_FLAG`.
